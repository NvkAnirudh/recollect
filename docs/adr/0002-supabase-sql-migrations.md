# 0002. Supabase, plain SQL migrations, psycopg

Date: 2026-10-18 · Status: Accepted

## Context
We need Postgres with vector search, user auth, and file storage (thumbnails). The core
query is a hybrid search SQL function (pgvector + full-text) with row-level security.

## Decision
- Supabase provides Postgres (+pgvector), Auth (JWTs) and Storage.
- Schema lives in `supabase/migrations/*.sql`, managed by the Supabase CLI. `supabase start`
  runs the whole stack locally, the same way as production.
- The backend uses psycopg 3 with hand-written SQL in a repository layer. No ORM.
- Every table has RLS enabled. The backend also scopes every query by `user_id`.

## Consequences
- SQL functions, RLS policies and indexes are first-class, not raw SQL buried in an ORM.
- There are no autogenerated migrations; developers write SQL. `supabase db lint` runs in CI.
- Applied migrations are never edited; changes are always a new migration.
